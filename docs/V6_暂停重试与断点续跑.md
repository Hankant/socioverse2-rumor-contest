# V6 暂停、按键继续与断点续跑

更新日期：2026-10-22。恢复组件版本：`interactive-recovery-v1`。这是运行机制修订，未修改人群、帖子、全部评论阅读规则、逐项条件要求、相信阈值或政府投放规则。

## 1. 现在发生错误时怎样处理

真实运行入口连接了前台恢复控制器。程序先完成已有的有限自动重试；仍失败时，保存完整轮次、已返回的请求响应、成功响应缓存、累计用量和诊断，然后显示暂停菜单。常见暂停不再以一段通用 RuntimeError traceback 结束。

菜单显示最后完整轮次、错误类别、累计请求/预算、成功缓存数量、结果目录、请求日志目录和待确认的未知请求。

| 操作 | 具体行为 |
| --- | --- |
| 回车 / R | 处理问题后再尝试。额外开启一组有限重试，保留全部原始请求与累计用量。 |
| W | 输入等待分钟数，默认60，可填1—720；时间到后尝试一次，再失败则重新显示菜单。不是无限自动重跑。等待时每30秒提示进度，Ctrl+C返回菜单。 |
| L | 输入新的单次输入代理token上限、累计输入预留预算、累计输出预留预算。回车保留当前值，只能提高；不改变单次输出token上限、请求次数上限或实验参数。 |
| U | 对菜单列出的“已发送但没有完整响应”的请求确认重发。必须完整输入 `REISSUE`；原未知记录保留，新请求再次计入预算，也可能再次产生费用。 |
| D | 查看最近请求的安全诊断、预算和未知请求列表，不显示API密钥。 |
| S / Q | 保存退出。退出前明确显示“本次实验尚未完成”和可续跑目录。 |

在主菜单按Ctrl+C或遇到输入结束，相当于保存退出。字母输入后需按回车。

## 2. 不同问题有什么区别

- **接口限流、额度用尽、主副接口都不可用**：显示 `QuotaPause`，可等待额度恢复后R，或W等待300分钟等你需要的时间。按继续不等于供应商已经恢复额度。原主副API策略继续使用：优先主API，符合条件的失败切副API，之后每小时由后续请求触发一次主API探测。
- **完整评论和记忆超过输入上限**：显示 `PromptBudgetPause`。直接R无效，程序留在菜单；选择L明确提高上限，或S。当前校验允许单次输入代理上限512—131072，仍受供应商实际上下文与额度约束。不会截掉评论或记忆来强行继续。
- **累计token预留预算到顶**：显示 `HardBudgetPause`。L可以明确提高相应token预算；预算不自动增加。已经用尽请求次数时，本菜单不会重置或提高次数，需要保存退出。
- **逐项条件输出反复不完整**：显示 `DecisionConditionsPause`。R开启新的一组最多4次生成尝试。旧回答仍在审计中；不会将缺条件的回答当作成功，也不会替LLM编造判断。
- **响应被截断、空响应或语义校验失败**：暂停后可以检查日志，再R重新生成。R不会改变提示词或单次输出上限；如果反复出现截断，应先检查生成长度与输出结构，不能靠无限按R解决。
- **请求超时或强制中断导致结果未知**：已成功缓存的请求不重复调用；没有完整响应的请求必须走U确认。R不会悄悄重发。即使用户确认重发，原请求的真实计费和服务器端结果也不能由程序推断出来。
- **密钥认证/权限问题**：菜单D可查看安全诊断。可在另一个终端运行 `./.venv/Scripts/python.exe scripts/manage_api_keys.py set`，通过隐藏输入更新本地加密密钥，然后返回原菜单R。不要在菜单或配置文件里粘贴密钥。新客户端会重新读取密钥。

多个并行请求可能同时触发“输入超限”和“结果未知”。选择L或U后，程序允许在同一次操作中同时明确调整上限、确认重发，不会陷入两个条件相互阻塞的菜单。

## 4. 如何主动暂停与稍后恢复

运行时按一次Ctrl+C：并发调度器停止补发新任务，唤醒还在排队的任务，等待已经发出的请求收尾并保存成功响应，再进入菜单。网络调用本身的超时设置仍为90秒，收尾可能需要等待；请等菜单出现。

在菜单按S退出后，双击项目根目录新增的 `Resume-V6.cmd`，或运行：

```powershell
& '.\.venv\Scripts\python.exe' -u '.\app_v6\local_cli.py' resume
```

省略目录时读取 `runs/v6/latest.json`。该指针表示最近一次本项目运行，可能指向离线测试或旧实验；启动前会显示具体目录，并检查兼容性，不会猜测另一个实验自动续跑。

指定一个确认的目录：

```powershell
$savedRun = 'E:\papers\socioverse 2026\socioverse2_v6_local\runs\v6\这里替换为需要续跑的完整目录名'
& '.\.venv\Scripts\python.exe' -u '.\app_v6\local_cli.py' resume --parent $savedRun
```

或使用PowerShell入口：

```powershell
.\Run-V6.ps1 -Mode Resume
# 指定目录时：
.\Run-V6.ps1 -Mode Resume -ParentRun $savedRun
```

恢复已暂停的实验会先显示菜单，等你选择R/W/L/U/S。已完成的实验提示无需续跑。

## 5. 续跑会复用什么，重新计算什么

1. 检查原实验的代码哈希、素材哈希、配置、运行模式、NumPy版本、上游版本和总轮数。只允许明确提高上述三种执行上限；不允许改人群、提示词或传播设定后接续同一实验。
2. 校验从第1轮开始连续存在的完整检查点：每轮必须有582个不同用户、正确轮号和匹配校验和。
3. 为本次恢复建立新的结果、配置和审计目录，记录 `resumed_from`；原结果不覆盖。原审计及预算复制到子运行，不清零。
4. 重放已经完整提交的轮次，仅使用存下来的行为，不调用LLM，重建环境和个人记忆。
5. 进入未完成轮次，以相同观察生成相同请求签名；有效缓存直接复用。只对缺失或明确批准重新生成的决策发起新请求。
6. 所有582人的本轮决策均成功后，才提交整轮、写入指标和检查点。错误发生在第6轮时，最后完整轮次仍然可能是5。

交互重试授权记录在新审计目录的 `recovery_authorizations.json`。它只划定额外一组重试的历史分界和具体未知请求的重发许可；不会删掉原请求，不会改成“已知成功”，不会抹掉支出。

单进程锁在菜单和等待期间继续持有，防止同时开启第二个实验并共同消耗预算。保存退出后释放。每次恢复会复制审计并产生新的轨迹，因而增加本地磁盘占用。

## 6. 旧实验和强制关机的边界

截图里的 `government-rumor-v6-openai-20261022-173105-065163` 使用更早的人群/判断与阅读实现，不能与当前完整评论、二分类、逐项条件版混接。它前5轮的数据保持原样；使用新启动器恢复该目录会明确提示版本不一致，而不是偷偷迁移。

本次修改本身也会改变代码哈希。因此修改前的其他运行不会自动视作同版本运行；以后使用本次版本启动的实验，只要代码与素材保持不变，就可以通过以上菜单恢复。若在暂停后修改代码/Prompt，需要新实验或另行设计、核对具体迁移，不能把它当作普通重试。

直接关闭窗口、断电或强杀进程，Python无法保证再写最后一条状态。已经原子写入的完整检查点、缓存和预留账本仍是恢复依据；最后未收到响应的请求可能被标为未知，恢复时需确认。若磁盘损坏或审计/检查点被删除，恢复程序不会猜测补造数据。

输入代理token上限、实际服务上下文、累计预算和评论增长是独立约束。增加恢复菜单可以避免“失败后直接退出”，不能保证所有参数设定都必然完成10轮，也不能使耗尽的外部额度恢复。

## 7. 无人值守批处理

真人终端默认启用菜单。没有交互stdin（重定向、管道）时不会挂起等按键：保存后以退出码2返回。可显式禁用菜单：

```powershell
& '.\.venv\Scripts\python.exe' -u '.\scripts\run_live_checked.py' --no-interactive-recovery
# PowerShell入口：
.\Run-V6.ps1 -Mode Live -NoInteractiveRecovery
```

退出码0既可能表示完成，也可能表示用户选择保存退出；应结合 `status.json` 判断。暂停的无人值守运行返回2，配置/版本错误也返回2。主程序的异常详情以本地诊断为准，不依据退出码声称实验完成。本次没有重新启动已被用户终止的54组批量任务。
