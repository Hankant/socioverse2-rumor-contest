## 三、Prompt具体改动

1. 明确私下的相信倾向、核实状态和公开表态分开。“尚未核实”可以影响判断，不直接等于uncertain。
2. believe表示更偏向事情发生；reject表示更偏向没有发生；uncertain表示没有明显方向或相互矛盾的印象使其难以偏向。
3. 明确现有source_prior、government_prior、verification_preference、sharing_propensity和repetition_sensitivity的相对行为含义，结合MBTI风格和具体生活背景形成角色反应。
4. 评论和转发继续自主选择，不把分享等同于相信，不规定总体相信率，也不通过程序随机制造相信者。
5. evidence_ids继续使用原字段名，但说明它只记录参与判断的已接触内容ID，不表示已经独立证实。
6. 新增资料属于合成背景，年龄、地区、职业和人格字母不能直接推导轻信程度。角色只知道实际看见的帖子与记忆。

## 四、新增测量及完整保存链路

每次真实LLM回答除原belief、comment、repost、evidence_ids外，必须包含：

```json
{
  "subjective_credibility": 0,
  "component_credibility": {
    "funds_redirected": 0,
    "safety_delayed": 0,
    "causal_link": 0
  }
}
```

上面0仅展示数值字段的位置，不是固定输出或默认值。每项允许0—100有限数值与小数；布尔、字符串、缺失、NaN或越界值均不接受。字段不合格时按已有格式重试规则处理，不用默认分数补齐。

- subjective_credibility：完整核心说法的主观可信度。
- funds_redirected：相关安全整改资金被调往商业街立面与景观。
- safety_delayed：相关安全整改被延后。
- causal_link：前述资金调整导致了安全整改后排。

分项是测量问题，不是额外事实提示。评分由LLM自报，不能当作校准后的人类概率，也不把来源信任直接复制为评分。原belief原样保留，不用阈值自动重写，因此可检查“uncertain但评分偏高”等现象。

保存链路为：原始API回答 → 严格校验 → 行动检查点 → 当前状态 → 最近5次成功经历 → 面板 → `trajectory/belief_measurements.csv`。该CSV按已完整提交轮次导出年龄、地区、职业、MBTI、belief、完整及分项分数。初始未报告为null/空白；规则角色没有LLM评分，状态明确为not_applicable_rule，不伪造0分。
