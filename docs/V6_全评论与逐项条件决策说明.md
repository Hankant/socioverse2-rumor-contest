# 网络触达主帖、完整评论与逐项个人条件

当前版本：`v6-network-thread-all-conditions-20261022-1`。详细接触机制见 [网络触达与完整评论](V6_网络触达与完整评论.md)。

当前按用户确认：关注SOURCE的用户初始看到P001，其他人通过关注账号的转发首次接触；接触后每轮可回看同一个原帖及其截至上一轮的全部评论，未接触者不获原帖或评论。政府通过独立账号发帖。模型仍为MiniMax-M3，305名LLM用户＋277名规则用户，完整说法评分>50相信、≤50不相信。

## 1. 每轮实际看见什么

| 项目 | 当前实现 |
|---|---|
| 谣言主帖 | 网络决定首次接触：初始82名SOURCE关注者；其他人经关注账号的转发接触，已接触者每轮可回看同一P001 |
| 谣言评论区 | P001及其转发下面截至上一轮的所有评论；包含非关注者，不截取最新2条，不筛选立场 |
| 谣言转发 | 仍记录转发动作、作者、附言和网络关系；阅读视图中归并为同一个P001，不生成额外谣言阅读槽位 |
| 政府账号 | GOVERNMENT独立发布G001，不在SOURCE帖子下充当官方评论 |
| 政府触达 | 保留配置中的介入轮次、100人投放及80%/20%圈内配额；其他用户通过关注账号的转发接触官方正文 |
| 政府评论区 | 只在官方帖实际展示时附带G001及其转发下的全部先前评论，与P001评论区分开 |
| 触达官方后 | 已成功读到官方帖的用户后续每轮可回看完整官方帖及评论 |
| 同步顺序 | 本轮所有人先观察上一轮结束的环境，统一提交后，新评论与转发下一轮才可见 |
| 评论对象 | LLM在comment.target_content_id中选择本轮实际展示的P001或G001；不再自动评论第一条 |

每人每轮最多有一个谣言主帖视图；若已接触官方帖，可另有一个独立官方帖视图。程序中保留转发记录，是为了保存行动和来源，不代表把同一谣言当成多条主帖展示。

关注网络决定首次获得P001的时间和范围，并决定可见转发附言及未直接投放者何时接触官方正文。原帖全部评论只对已接触原帖者展示，不会绕过网络提前送给未接触者。圈内/圈外同时保留SOURCE关注关系及来源信任差异。

公开谣言评论可能引用已看到的官方信息，因而官方观点也可能经P001评论传播。用户在评论里读到引用，不等于程序已向该用户展示完整G001。这是公共评论区开放后自然存在的间接接触，不能把所有官方信息知晓都归因于100人直接投放。

## 2. 每项个人条件必须说明如何应用

当前策略为 `decision_condition_policy=all_conditions_v1`。每个LLM用户都有11项必须使用的本轮条件：

| 字段 | 条件 | 要求的作用 |
|---|---|---|
| age | 年龄 | 结合给定年龄形成角色关切、理解或表达方式 |
| region | 合成居住地区与居住环境 | 结合生活环境形成关联感，不虚构该地项目事实 |
| occupation | 职业 | 结合给定职业的日常视角和表达 |
| community_experience | 社区工程和事前经历 | 区分给定的其他项目经历与本案例事实 |
| mbti_preferences | MBTI与个体偏好强度 | 实际体现信息处理和公开表达风格 |
| source_trust | SOURCE信任 | 使用本组实际分配的个体信任值，覆盖人口表旧默认 |
| government_trust | 政府信任 | 结合实际已见信息应用；未读官方正文时不能预知其结论 |
| verification_preference | 核验偏好 | 影响检查细节、来源和矛盾的方式 |
| sharing_propensity | 分享倾向与习惯 | 影响是否参与、是否转发及附言方式 |
| repetition_sensitivity | 重复敏感度与实际接触记录 | 根据真正接触次数形成熟悉感，首次接触不能编造重复效应 |
| history_and_memory | 上轮状态、评分及最近5次经历 | 接续本人此前反应，可保持也可改变；初始空记忆须如实处理 |

LLM需要综合全部条件形成评分和行动，再为每一项返回一个简短应用摘要，不要求长篇思维过程。格式如下，示例只展示一个键；实际必须完整返回11项：

```json
{
  "condition_context_ref": "本轮输入中给定的16字符标识",
  "condition_application": {
    "age": {
      "affects": ["comment"],
      "note": "结合本人年龄背景，用符合角色的口吻表达对安全整改的关切"
    }
  }
}
```

`affects`只能从credibility、comment、repost中选择，至少一项；`note`必须为4—60个字符，不能空白、同上或只写“已考虑”。同一条件无需机械改变全部三个结果；某些条件可以落实到评论或分享方式。角色没有的项目知识不能凭年龄、地区或人格补造。

代码检查11项键的完整性、作用对象和摘要结构。本轮输入标识由程序依据实际观察绑定，保留模型原始返回值；明确的同义字段名会作机械适配，完整11项之外的补充说明另存，不能因此补造缺失条件。详见 [输出格式重试修复](V6_输出格式重试修复.md)。遗漏任一真实条件的回答不进入有效缓存或状态；最多4次生成仍不合格时，整轮暂停为 `paused_decision_contract`，保留已完成轮次及成功响应，不把缺失条件的回答当作有效行为。

**这是一种可审计的输入和输出约束。它不能从技术上证明基础模型内部对每一项都赋予了非零因果权重，也不应强迫模型伪造固定加减分。**实际作用是否符合预期，还需对照更改单一条件的实验和逐人摘要检查；程序不会把“结构覆盖通过”称为“已经证明真实因果影响”。

## 3. 相信、评论与转发

完整说法的 `subjective_credibility` 仍是最终分类唯一分数：>50相信、≤50不相信，50归不相信。三个事实分项用于分析，不取平均替代完整分数。

评论和转发仍分别由LLM选择，相信不要求必须转发，不相信也可为质疑或求证而转发。每人每轮最多评论一处、转发一次；同一根内容全程最多成功转发一次。评论必须显式指向实际展示的主帖，转发对象也必须实际可见。

277名规则用户仍按PB=.579、RC=.10及个人GT/RF=.60执行，不生成自由评论、不对评论正文进行语言推理。新阅读结构会改变其接触和抽样机会，因此规则公式数值相同不代表累计过程与旧版相同。

## 4. 输入长度和预算

所有已可见评论都进入观察，最近5次完整经历继续保留。输入保护仍为32768个代理估算token，`prompt_memory_policy=preserve`。超过保护上限时，调用前暂停为 `paused_prompt_budget`，不会悄悄删评论或缩成两条。新模式拒绝trim_oldest配置。

为容纳11项说明，单次最大输出由768调至1536 tokens。总请求上限12200、总输入预留49,971,200及总输出预留6,246,400保持原值。按1536预留时，总输出预算最多容纳4066次新请求；失败重发和主副Key切换也占预留。若305名LLM每轮均成功决策，10轮需要3050次有效决策，额外请求仍受剩余预算限制。

公开评论增长后，尤其和最近5次经历重复携带时，可能在10轮结束前触发输入保护。完成结构性修改不等于保证每组实验都能在现有额度内跑完。本次没有修改MiniMax模型、采样参数、主副Key策略或账户账单设置，也没有启动真实API实验。

## 5. 如何运行和检查

双击项目根目录的 `Run-V6-Heterogeneity-Test.cmd`，仍只运行D040/T02/C080/G075一组10轮，API并发上限2，并自动读取本机加密Key。

也可在PowerShell执行：

```powershell
Set-Location -LiteralPath 'E:\papers\socioverse 2026\socioverse2_v6_local'
$env:PYTHONIOENCODING = 'utf-8'
.\.venv\Scripts\python.exe -u scripts/run_live_checked.py --gap 0.4 --tg 2 --target 0.8 --gt 0.75 --steps 10 --concurrency 2
```

每执行一次都会新开一组实验。旧版本检查点不能直接接入这个新阅读结构；旧结果和已终止的54组队列保持原状，未自动重启。

检查实际使用情况：

- `trajectory/condition_applications.csv`：每个已提交的LLM决策有11行，包含条件名、作用对象、应用摘要、输入标识、分数和分类。
- `trajectory/belief_measurements.csv`：每人每轮可信度和三个事实分项。
- `checkpoints/tick-*.json`：完整观察、评分、显式评论/转发及逐项摘要。
- `runtime/v6/logs/<运行ID>/request-*.json`：原始Prompt和原始回答，仅成功校验结果才用于有效状态。
- `status.json`：区分真实完成、输入保护暂停、决策合同暂停和额度暂停。

主要实现：`app_v6/model.py`、`app_v6/decision_conditions.py`、`app_v6/llm_client.py`；固定Prompt在 `materials_v6/02_Prompt固定提示词.md`。
