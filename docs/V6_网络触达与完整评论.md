# 网络决定首次接触，已接触者读取完整评论

当前版本：`v6-network-thread-all-conditions-20261022-1`。
当前阅读策略：`network_rumor_all_comments_v1`。

## 1. 本次确认的四条规则

1. 初始只有关注谣言博主SOURCE的用户看到P001原帖。
2. 其他用户通过自己关注的账号转发，首次接触P001。
3. 接触原帖后，可以每轮回看同一原帖及截至上一轮的全部评论，包括非关注者的评论。
4. 尚未接触原帖的用户，不接收原帖或其评论；公开评论本身不绕过首次接触条件。

全体582人仍参与每轮模拟；“参与模拟”与“接触原帖”是两件事。没有任何可见帖子的用户本轮idle，不调用LLM，不产生评论或转发，也不把“没看到”归成“不相信”。他们保持unjudged，直至实际获得信息并完成判断。

## 2. 现在第一轮到底有多少人看到

固定人口与关注网络保持原值：582名用户，其中圈内82人关注SOURCE，圈外500人未关注SOURCE。每人关注8名同圈用户、2名异圈用户，圈内另有SOURCE关注边，合计5902条有向边。

因此第一轮：

| 人群 | 看到原帖 | 尚未看到 |
| --- | ---: | ---: |
| LLM用户 | 43 | 262 |
| 规则用户 | 39 | 238 |
| 合计 | 82 | 500 |

初始覆盖率为82/582，约14.09%。这些是人口与接触机制的确定值，不是真实MiniMax决策结果。第一轮82人是否相信、评论、转发，仍由既定的LLM或规则机制产生。

只要没人转发原帖，圈外用户就不会凭空收到P001，即使原帖下面有很多公开评论。若有人转发，则下一轮沿其粉丝关系产生新的接触者，随后可继续多跳传播。

## 3. 一条明确的传播链

假设A关注SOURCE，B关注A，C关注B；B和C均不关注SOURCE：

| 轮次 | A | B | C |
| --- | --- | --- | --- |
| 第1轮 | 读原帖；若决定转发，提交转发 | 尚未接触 | 尚未接触 |
| 第2轮 | 可以回看 | 因A上一轮转发而首次接触；可读全部先前评论；若转发则提交 | 尚未接触 |
| 第3轮 | 可以回看 | 可以回看 | 因B上一轮转发而首次接触；可读全部先前评论 |

没有某一跳的转发，后面的接触就不会由这条链发生。关注边方向是“读者→被关注账号”，不能反过来传播。同轮刚提交的转发或评论，不会让排在后面的用户提前看见。

程序不会为每一次转发另造一个谣言主帖：内容仍归到P001。用户只看到一个原帖视图，`relay_context`保留自己关注账号的转发ID、账号、时间与附言。看过原帖后，每轮可进入同一讨论阅读完整评论，不需要每轮重新获得一次转发。

## 4. 全部评论的边界

获得原帖访问资格后，展示该主帖和其转发下截至上一轮的所有评论，保留评论ID、作者、时间与全文；不再限定2条。多条转发归并到同一根主帖，避免重复阅读同一原帖或重复附带同一评论。

没有原帖访问资格的人，即便关注了某条评论的作者，也不会仅靠评论获得P001。接触后，非关注者的评论可以影响判断，这是保留完整公共讨论的假设。因此网络决定首次进入讨论的时间，进入后评论影响可以跨越关注边。

重复接触按实际展示轮数累计；尚未接触者不累积熟悉感，不凭模拟已运行的轮数伪造“看过很多次”。评论和个人经历仍完整进入Prompt；最近最多5次成功经历不变，超出32768代理token输入上限时显示暂停菜单，不截断评论来继续。

## 5. 政府帖子仍为独立账号

GOVERNMENT在指定轮次发布G001，仍只直接投放100人，按条件保证80名或20名圈内用户；后续通过用户转发触达其关注者。官方评论区与P001评论区分开。

因此一个圈外用户可能先被政府定向触达，只看到G001。它不会自动获得P001或原帖评论；政府正文自身可能复述并回应原始主张，这是实际官方内容暴露，不等于系统已展示P001。用户可以基于已读官方信息判断主张，但不能引用或评论尚未展示的P001。

已看过G001的人后续可回看官方正文及其全部先前评论。接触P001的用户也可能在公共评论中看到其他人转述官方观点；这类间接信息不自动计作看过G001。

## 6. Prompt、行为和参数

首次从SOURCE看到原帖时，提示日常刷到已关注、喜欢的博主；圈外首次接触时，提示日常刷到关注账号的转发，并附真实可见的转发记录。之后根据真实个人接触历史提示回看。删除新策略中的“全体每轮都能看到同一原帖”描述。

年龄、地区、职业、社区经历、MBTI偏好、SOURCE信任、政府信任、核验偏好、分享倾向、重复接触、历史和记忆这11项要求保留。LLM仍给0—100主观可信度，>50相信，≤50不相信；评论和转发独立选择，每人每轮各至多一次，同一根帖全程至多成功转发一次。

277名规则用户的PB=.579、RC=.10、个人GT和RF=.60不变。规则用户不使用LLM解读评论；本次修改恢复其接触范围，不改变其概率公式。54组因素和数值不变，只同步新的阅读策略及版本标识。没有启动任何真实组别或恢复已终止的批次。

## 7. 怎样检查覆盖与结果

`trajectory/metrics_history.json`新增以下字段（rumor代表P001，official代表G001）：

| 字段 | 含义 |
| --- | --- |
| rumor_readers_this_tick | 本轮成功决策实际读取P001的人数 |
| rumor_new_reach | 本轮首次成功读取P001的人数 |
| rumor_cumulative_reach | 截至本轮至少成功读取一次P001的人数 |
| rumor_coverage_rate | 累计触达人数 / 582 |
| official_readers_this_tick 等同名前缀字段 | 官方帖对应的接触指标 |

`trajectory/belief_measurements.csv`增加rumor_seen、rumor_first_seen_tick、official_seen、official_first_seen_tick，便于逐人核查。尚未接触原帖者可能仅接触过官方帖，判断时应同时查看两种接触字段。

相信率继续以believe+reject为分母；另报unjudged人数。传播覆盖率与相信率分母不同，应同时报告，不能把剩余未接触者当作不相信者。

结果校验器会从冻结的关注网络逐轮重放已存动作，检查每个人是否有资格看到其记录的帖子、转发附言和完整评论，并核对输入没有未来内容。不能只看“582人×10轮有数据”就认定所有人都接触过谣言。
