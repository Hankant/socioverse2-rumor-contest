# V6 输出截断、空响应与有限自动重试修复（2026-10-23）

本次对应 `20261023-073508-609988` 的单组实验，参数 D=0.4、T=2、C=0.8、G=0.75。目标10轮，技术并发2。原实验前2轮完整，第3轮部分LLM决策已经成功缓存。

## 真实故障

第339次请求，A0326，第3轮，返回 `finish_reason=length`，输出1536 token。回答把131个证据ID写进JSON，导致后面的条件说明被截断。旧代码在这种情况下直接抛出通用 `ValueError`，没有进入格式重试。此前处理条件字段别名和上下文标识的修复没有覆盖这一分支。

修复前共有341份请求记录、314份成功决策缓存；第340和341次请求是并发中的其他用户，已经正常返回。第3轮尚未整轮提交，不能当作完整结果分析。

## 现在如何处理

新策略名 `bounded-output-feedback-v2`。适用于 `all_conditions_v1` 的真实LLM调用。

1. 先保留原始响应和计费记录，再识别结束标记、正文和JSON。
2. 截断、空正文、没有选择项、JSON语法错误、条件缺项、条件摘要错误、无效评分、非法行动结构、不可见证据或目标等情况，在原有最多4次生成范围内自动重试。
3. 下一次请求明确带上上次结构错误，例如 `truncated_output`、`missing_conditions`、非法条件字段或JSON错误位置；不会反复发送没有反馈的同一份提示。
4. 完整历史响应、每次实际发送的提示、预留预算及实际用量均保留。重启不会清零失败次数、累计预算或成功缓存。
5. 连续失败达到上限，保存为 `paused_output_contract`，显示具体代理、轮次、失败类别和次数，再进入交互菜单。R可以明确开启额外一组有限尝试，不会无限自动消耗额度。
6. 供应商明确拒绝生成直接暂停。已经发送但没有持久响应的请求继续使用原来的“结果未知”保护，普通重试不会擅自重发；需要原有U确认流程。

## 提示词的实际变更及研究边界

角色设定、事件原文、官方回应、当前观察、全部可见评论、最近5次完整经历、11项个人条件和原有研究提示均保持。新API请求末尾追加一段机器输出协议：输出完整JSON；11项摘要仍全部必需，每项4至60字符，建议8至24字符；证据引用仅选择0至6个实际可见的相关ID，避免抄写全部白名单。

“引用少量ID”只限制输出引用数量的提示，不减少读取的评论数量。程序仍严格检查每项条件说明、评分、证据和行动对象，不会把截断JSON补成结果，也不会用规则答案替代LLM失败。最终评分和是否评论、转发仍由MiniMax-M3生成。

新API提示确有输出协议变化；不能声称与旧调用的实际提示完全相同。`base_prompt`记录原研究提示，`prompt`记录实际发送的完整文本，`actual_prompt_sha256`是该实际文本UTF-8的SHA256。原 `prompt_sha256`继续作为包含模型、请求选项、代理和轮次的逻辑决策签名，用于可靠复用旧有效缓存。重试反馈不包含新的事件事实，也不要求提高或降低分数。

为保留已有进度，本次采用只针对确切父运行的哈希审查迁移。原始请求、缓存、前2轮检查点、预算、配置、模型、事件材料与受保护研究提示函数均核验。迁移清单明确记录输出协议变更；不能用于任意跨版本继续。

条件摘要是模型自述的输入应用说明，只能验证结构覆盖，不能证明每项属性在因果上改变了决策。

自动重试是让模型重新生成，并不是把失败回答改成合格答案。重新采样后的评分、评论和转发可能与那份失败回答不同；已经成功的314份历史答案逐字节保留。本次修复不保证新旧生成的行为分布完全相同，后续比较应保留版本和重试标记。
