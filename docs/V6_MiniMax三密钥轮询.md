# MiniMax 三密钥轮询与失败切换

当前Windows用户的DPAPI加密库已保留原主Key、替换副Key、加入第三个Key。代码、普通配置、审计日志不保存密钥明文。

## 调度

api_routing_policy=round_robin_v1；正常实际请求按 primary → backup → third → primary 循环。缓存命中不请求、不推进轮次。单次失败后在同一个逻辑决策中尝试其他可用密钥，模型和提示保持相同，不用规则答案代替LLM结果。

线程共享一个带锁的路由器；轮询游标、各路冷却截止时间及失败代次保存在本机无密钥的routing-round-robin.json，普通重启不重置冷却。更新加密密钥时重置路由，从主Key开始。

临时错误/限流默认冷却60秒；HTTP401/402/403或诊断含额度/余额提示时冷却3600秒。更长的Retry-After优先。冷却中的路被跳过，期满后在真实请求需要时重新加入循环，没有空闲时的额外探测调用。

三路都不可用时保存检查点和缓存并暂停，恢复菜单仍可等待后重试。一次逻辑决策不会反复循环调用已明确失败的路；所有路共用原来的累计请求、输入和输出预算，不因切换Key清零或扩大上限。

明确的供应商拒绝、认证问题、连接建立失败、可切换服务故障会尝试其他路。参数/模型/内容错误继续显示原因，不通过换Key掩盖。请求已发送但响应丢失时无法知道是否完成/计费，仍保存为未知结果并进入恢复流程，不静默重复提交。

## 配置与使用

当前单组启动器Run-V6-Latest100-ONE.cmd、本地默认和54组参数配置均启用三路轮询。最多2路并发、MiniMax-M3、最新100条评论、MBTI自愿评论、277名规则用户不评论及全部研究参数保持原设定。

查看密钥槽位（不显示Key）：

    .\.venv\Scripts\python.exe scripts/manage_api_keys.py status

以后只替换一槽，保留其他两槽：

    .\.venv\Scripts\python.exe scripts/manage_api_keys.py set-slot --slot backup
    .\.venv\Scripts\python.exe scripts/manage_api_keys.py set-slot --slot third

程序在隐藏输入提示处接收新Key。primary同样可更新。每槽必须不同。

本次使用本地模拟接口验证轮换和故障处理，没有联网验证供应商是否接受三把Key，也没有启动付费实验。密钥格式、加密保存和解密回读均已核对，主Key保持不变。

原主优先的两槽代码保留用于旧配置兼容；当前启动配置使用三槽轮询。旧实验不能绕过代码和配置一致性检查直接拼接运行。
