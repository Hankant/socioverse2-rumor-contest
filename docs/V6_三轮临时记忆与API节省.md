## 记忆此前是否生效

生效。真实请求 request-002198、request-002199 位于第 9 轮，used_memory_ticks 都是 [4,5,6,7,8]。旧代码在环境中固定保留最近 5 次成功经历，发送时把这些经历放入个人记忆，并在第 11 项 history_and_memory 中记录轮次与内容哈希。这个校验能证明输入和结构覆盖，不能证明 LLM 在行为上对每一条记忆产生了多大影响。

MiniMax 的独立请求不会因为本地存有记忆文件而免去输入：需要把允许读取的记忆随本次请求发送。保留多轮经历会继续占输入；提供商的前缀缓存可能降低重复部分的处理与计费成本。

## 新版三轮到期的精确定义

配置为 memory_retention_policy=rolling_simulation_ticks_v1、memory_window_ticks=3。它按模拟轮次到期，是滚动窗口：第 t 轮决策只允许读取 t-3、t-2、t-1 轮中本人实际产生的经历。第 4 轮读取第 1～3 轮；第 5 轮读取第 2～4 轮；第 9 轮读取第 6～8 轮。中间没有行动也照常计时，不会变成“保留最近 3 次行动直到很久以后”。

这不是每逢第 3、6、9 轮把全体记忆同时清空。原始行动、请求和公开评论仍在本地留档；到期内容从 LLM 的个人经历输入中移除。

以下持久状态继续保留，因为传播、重复接触和信念更新需要它们：当前相信/不相信、当前评分、累计接触次数、是否已经接触原帖、是否已经转发某根主帖、网络关系。到期不会把人重置为未接触，也不会允许重复转发。旧经历对当前信念的间接影响可能仍然存在。

公开评论与个人记忆有不同的到期规则。三轮前的评论如果仍属于当前主帖最新 100 条，也可能作为当前公开材料再次出现；这不是从已到期的个人记忆中读取。

## 真实消耗与离线节省测算

原始请求日志累计记录：输入 26,554,519 token，输出 907,653 token，输入占二者合计约 96.69%。这是接口返回的 token 数，不是订阅平台最终扣减额度；37 条请求错误没有可确认的实际 usage，不能把它们当作免费或额外固定收费。

对既有日志中 1,966 个“用户×轮次”的首个收到响应的请求，固定其已观察材料与既有经历，离线移除三轮前个人经历，再重新编码：输入正文的代理估算量总计下降约 0.947%；第 8 轮约 2.823%，第 9 轮部分样本约 3.288%。早期轮次原本没有超过三轮的经历，新增到期规则说明反而占少量输入。

这个比较只核算输入正文，未计输出协议后缀；使用本地 tokenizer 的代理估算，不是 MiniMax 账单，也不是重新运行后产生的新行为结果。新版真实评论与评分可能改变，不能承诺后续节省比例。记忆较小的原因是上一版已经不再把旧公共评论全文作为个人记忆反复输入。

## 本次进一步做好的节省措施

新的 wire_prompt_style=concise_shared_prefix_v1 把相同规则、格式说明和本用户实际可读的材料库前置，再放角色编号、个人资料、当前状态与记忆。此前用户编号位于开头，相邻用户很快出现前缀差异。新版使同轮相同帖子和评论有机会命中相同前缀。

排列调整不删除资料、评论、条件或行动字段；可逆解码测试检查内容、顺序、引用边界与原文。它仍然只给每个人本来可见的内容，不从其他用户或全局评论档案添加材料。提示排列可能影响随机 LLM 的输出，不能把内容保留理解为每次分数必然相同。

MiniMax 官方说明 M3 支持 ≥512 输入 token 的自动缓存，使用前缀匹配，推荐共同内容在前、动态信息在后。OpenAI 兼容接口的 prompt_tokens 包含缓存输入；缓存命中量由 prompt_tokens_details.cached_tokens 返回。官方文档列出的缓存折扣是计费说明，不能直接套为本账号订阅额度的折扣。

现在每个响应日志增加 cached_input_tokens 和 reasoning_output_tokens；供应商未提供时记 null，不假记为 0。旧日志未记录缓存明细，因此旧命中率未知。实际缓存命中、三把 Key 是否共用缓存、缓存寿命及订阅额度收益需要下一次真实运行测量，离线相同前缀只是命中机会。

- https://platform.minimax.io/docs/api-reference/text-openai-api

其他已经生效的措施：M3 thinking.type=disabled；精简结构输出和有限格式重试；同一观察下复用已成功回答；断点重启不重复生成已缓存结果；正文及重复材料按库去重；旧公共评论不作为历史记忆全文再次输入。单纯降低并发只会改变速度，不能减少相同工作量的 token 总数；只调低 max_tokens 也不会缩短输入，过低会增加截断重试。
