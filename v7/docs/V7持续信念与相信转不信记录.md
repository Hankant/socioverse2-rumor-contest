# V7持续信念更新与用户转换记录

修订日期：2026-10-27。运行版本：`v7-belief-history-reinforcement-20261027-1`。

## 本次选择的机制

保留LLM自主评分。程序将上一次信念值、实际接触次数、博主信任和政府信任明确交给LLM，要求综合更新，但不在LLM回答后自动增加或扣除分数，不设置预期的相信人数。该设定来自本次确认的选择。

持续信念使用已有的 `subjective_credibility`，范围0—100。对博主和政府的来源信任各自是0—1，三个数值不混用。`subjective_credibility > 50` 为相信，`<= 50` 为不相信；50分归不相信。此前没有接触信息的用户仍为 `null / unjudged`，不能把没有接触当作0分或预先给50分。

## 每轮怎样更新

1. 网络决定实际接触：初始只有关注SOURCE的48名圈内用户看到原帖；其他用户通过关注对象的转发首次接触。已接触者可以回看主帖。未接触者不提前得到正文、评论或模型调用。
2. 读取该用户上一次已提交的分数、个人资料、最近3个模拟时间步的临时记忆、累计实际接触记录，以及本轮可见内容。每个可见主帖最多保留截至上一轮的最新30条评论供判断。
3. 生成 `belief_update_context`，同时提供之前的原帖/官方帖阅读轮数、本轮是否阅读、计入本轮后的阅读轮数、重复轮数、实际到达方式和可见关注者转发数。重复轮数等于累计阅读轮数减1，最低为0。同一主帖同一轮仅计一次，多名关注者转发不冒充多份独立核实。
4. 要求LLM以上次分数为起点：实际重复接触可以增强熟悉感、巩固已有相信；结合博主信任、重复敏感度、核验偏好判断是否强化、维持或被相反信息抵消。求证、质疑和反驳式转发不能自动当作支持。
5. 只有实际看到官方回应后，政府信任才参与对该回应的接受。提示词明确要求：其他已见条件相同时，政府信任越高，通常越重视其核查与否认，越倾向下调原说法的分数。未接触者不能预知官方内容。
6. LLM自主返回新的信念值、是否评论和是否转发。程序校验分数、条件摘要、证据ID和行动对象后，直接保存该分数并按50分阈值分类。来源信任、政府信任及其他个人条件仍共同作用；没有固定的信任到分数计算公式。
7. 全体用户的该轮行动提交后，保存检查点、逐轮人数及真实转换记录。未完成轮次不计入最终记录。

例如，上次65分，本轮看到关注者再次转发，LLM可以给72分，也可以因反驳评论给45分。程序不额外加分。若实际看到官方回应并给45分，则记录65到45的相信转不信；也允许LLM综合判断后仍给65分。

## 临时记忆和持续状态

最近3个模拟时间步的临时经历会到期清除。已提交的当前分数、累计接触次数、是否已经转发、相信阶段起点和已发生转换事件持续保留。清除临时记忆不会把分数重置为50，也不会把用户变回未判断。

这表示用户不再收到过期经历的完整细节，但仍收到当前判断和累计接触统计。断点恢复通过已提交的逐轮行动重建这些状态，重复应用相同已提交行动不会重复增加事件。

## 只记录实际相信转不信

每次记录须同时满足上一状态 `>50`、本次状态 `<=50`。以下情况均不新增记录：未判断直接不相信、一直不相信、一直相信、尚未从相信转为不相信。

如果一个用户经历 `70 → 40 → 80 → 30`，记录两次事件，分别属于第1段和第2段相信阶段。再次相信会开启新阶段。没有发生转换的人不填0，也不在事件表中列一行。

| 主要字段 | 定义 |
| --- | --- |
| `agent_id` / `group` | 用户ID / inside或outside |
| `episode_number` | 该用户第几段相信阶段 |
| `believe_started_tick` | 该段首次评分>50的轮次 |
| `reject_tick` | 从该段相信转为<=50的轮次 |
| `believe_duration_ticks` | reject_tick减believe_started_tick |
| `score_before` / `score_after` / `score_change` | 转变前分数、转变后分数及差值 |
| `ticks_from_government` | 转变轮次减政府发布轮次；发布前的转变留空，发布当轮为0 |
| `official_seen_at_transition` | 转变时是否实际读过官方帖；仅已读不证明因果 |
| `official_shown_in_transition_tick` | 本轮是否实际阅读官方帖 |
| `rumor_read_rounds` / `official_read_rounds` | 转变时两类内容的累计阅读轮数 |
| `source_trust` / `government_trust` | 该用户实验开始时分配的两类来源信任 |

时间单位为抽象模拟步，没有现实小时或分钟映射。例如第2轮开始相信、第5轮不相信，持续时间为3步。此前的TBU按政府介入前一轮冻结的相信队列计算；它与这里每一段相信持续时间的起算点不同，保留原指标，不混用。

实验结束仍相信的人没有完成转换，其持续时间属于右删失，不写进实际转换事件表。只对事件表求平均，得到的是已完成转换者的平均持续时间，不能直接当作全体用户的平均纠正速度。

## 结果保存位置

每个新运行目录内：

- `reports/belief_to_reject_events.csv`：只有真实跨阈值事件，UTF-8 BOM，可用Excel打开；没有事件时只有表头。
- `reports/belief_to_reject_summary.json`：事件数、发生变化的用户数、政府发布前的事件数、未读官方帖时发生的事件数。
- `trajectory/belief_measurements.csv`：逐人逐轮分数，新增上一分数、分数差、是否发生转换，以及当前相信阶段的起点和累计转换次数。
- 后续新批次的每组Excel新增“相信转不信记录”页，逐轮人数和分类型人数页保留。

转换CSV在完整轮次保存后更新。CSV被Excel独占锁定时，原始检查点仍保留，并记录待导出状态；关闭占用文件后可再次离线导出。

## 不调用API的历史补导

历史运行已经保存逐人分数和接触记录，可以据此补算真实转换事件。补导只做测量，不能把旧版模型的行为变成新提示词产生的行为。为保留原始结果，应指定新的输出目录：

```powershell
Set-Location 'E:\papers\socioverse 2026\socioverse2_v7_local'
& '..\socioverse2_v6_local\.venv\Scripts\python.exe' `
  '.\app_v7\transition_report.py' `
  --run-dir '替换为某次完整或暂停运行的结果目录' `
  --output-dir '替换为单独的新导出目录'
```

只读取完整提交的时间步，不读取半轮回答缓存，也不构建API客户端。

## 研究解释的边界

提示词让相关条件明确进入输入，条件摘要提供回答自报的使用线索。它们不能保证每次评分都按某个方向变化，也不能证明LLM的因果机制。若要验证政府信任的作用，仍应对同一观察材料、同一旧分数和其他相同条件，仅改变政府信任做配对比较，并进行重复试验。政府信任较高者转变更快，也可能伴随接触时间、内容或其他背景差异。

本次未增加校准得到的强化系数，也未强迫模型提高相信比例。这样保留了本次选择的LLM自主评分机制。
