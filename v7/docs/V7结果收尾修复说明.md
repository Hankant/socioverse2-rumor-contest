# 2026-10-26 结果收尾修复

本次批任务曾显示31组完成、23组控制器错误。其中22组已经保存10轮完整检查点，失败发生在Parquet导出；另外1组保存9轮，原始暂停原因是第10轮的一次API读取超时。

原始导出使用256MB数据库内存限制。真实3300行数据复现了Parquet编码分配失败。异常处理又重复调用finalize，第二次创建已存在的metrics表，产生CatalogException并掩盖原始OutOfMemoryException。

## 修复

- 活跃模拟仍保持每组1个数据库线程和256MB预算。依次进行的收尾导出单独使用1GB上限。
- finalize失败后关闭数据库连接，重复调用直接返回，保留第一次错误。
- 原始错误及清理阶段错误分别保存诊断，控制器也保存异常发生位置。
- 批任务needs_attention返回非零退出码。退出码0不再掩盖未完成状态。
- 已保存结果可直接重放核验并补导出。原数据库、检查点、API缓存和预算保留；补导出不会构建LLM客户端。

22组完整数据已按原检查点核对每名用户、每个时间步的状态并恢复导出，过程中新增API调用为0。剩余1组按原先授权的有上限网络重试政策继续运行，不重跑已保存的前9轮或第10轮有效缓存。

验证包括233项离线测试，以及真实3300行数据的导出行数和内容哈希对比。实验人数、提示词、随机种子、网络、模型和执行预算没有修改。
